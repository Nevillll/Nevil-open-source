# 7.1 设计原则

## Apple 当前的设计原则（HIG《Design principles》）

HIG 在 2026-06 重新加入了一页《Design principles》（页面更新记录："Reintroduced design principles"），列出八条。下表是原文要点和本规范在网页上的落地方式：

| 原则 | HIG 原文要点 | 在网页里意味着 |
|---|---|---|
| **Purpose 目的** | 先弄清什么对用户最重要，把这些做好；每个阶段都问"这个设计是否服务于产品目的" | 每个页面写得出"用户来这里要完成什么"；与该目的无关的元素删掉，不为"看起来丰富"加卡片和图表 |
| **Agency 自主** | 不挡路，让人直接到达任务和内容；可以自由探索、不被锁在流程里；容易从错误中恢复 | 首页就是最常用的功能；引导流程可跳过；常见的删除操作提供"撤销"，而不是每次弹确认框 |
| **Responsibility 负责** | 透明说明产品做什么、为什么；只收集需要的数据并妥善保护 | 请求权限、收集信息时说明用途；不收集用不到的字段；敏感数据默认隐藏（见 06-frontend.md 安全部分） |
| **Familiarity 熟悉** | 使用人们已知的概念；外观和交互保持一致；提供清晰反馈 | 用标准控件和常见模式（顶栏、侧边栏、表格、表单），不发明新手势；同一种操作全站同一种样子 |
| **Flexibility 灵活** | 为所有人设计，从一开始就把无障碍当优先事项；保持用户的上下文；支持多种输入方式 | 手机、平板、桌面都能用；键盘、鼠标、触屏、读屏软件都能用；窗口缩放时控件位置可预测 |
| **Simplicity 简洁** | 只放必要的东西——"简洁不是极简"；用词精炼；建立层级 | 次要功能放进菜单或下一层（渐进披露）；一屏一个重点；按钮文字两到四个字说清 |
| **Craft 工艺** | 每个细节都体现用心；早做原型、反复迭代；上线不是终点 | 对齐、间距、文案逐一检查；交付前跑 [09 设计审查清单](09-review-checklist.md) |
| **Delight 愉悦** | 想清楚要唤起的情绪；不要把装饰误当成愉悦；考虑整体 | 管理类工具的"愉悦"来自快、准、稳，而不是动画和插画 |

## Liquid Glass 设计语言的三条原则（2025）

Apple 在 WWDC25 推出 Liquid Glass 设计语言时，用三个词概括它的设计原则：**层级（establish hierarchy）、和谐（create harmony）、一致（maintain consistency）**（Apple Developer《Liquid Glass》技术概览；WWDC25《Platforms State of the Union》）。在网页上：

- **层级**：控件和导航是浮在内容之上的"功能层"，内容是主角。网页做法：顶栏/侧边栏/底部标签栏与内容在视觉上明确分层（背景层级令牌 `canvas / surface / elevated`），层级主要靠**布局和分组**表达，而不是靠装饰。
- **和谐**：控件形状与设备、内容协调，嵌套的圆角保持同心。网页做法：内层圆角 = 外层圆角 − 内边距；圆角只用令牌里的几档。
- **一致**：使用标准控件、统一的导航与搜索模式、可预测的操作位置。网页做法：所有页面共用同一套布局骨架和组件；"新增"按钮永远在同一个位置。

> 关于"Clarity / Deference / Depth（清晰、遵从内容、纵深）"：这是早期 iOS 版 HIG 提出的三个主题，当前 HIG 已不再单独列出，本仓库未能打开旧版原文核对，只作为背景了解。它们的精神已体现在上面的原则中：清晰 ≈ Simplicity；遵从内容 ≈ 内容是主角、控件不喧宾夺主；纵深 ≈ 层级。

## 本规范由此得出的取舍

1. **内容优先于装饰**：不加无意义的渐变、插画、阴影堆叠；毛玻璃（`backdrop-filter`）只可用于浮在内容之上的导航层，并且必须保证文字对比度，不用于内容区。
2. **熟悉优先于新颖**：先用 HTML 原生元素（`<button>`、`<a>`、`<input>`、`<select>`、`<dialog>`、`<table>`）；原生做不到的复杂组件（下拉菜单、组合框、标签页）用遵循 WAI-ARIA 规范的成熟无头组件库实现，选型写 ADR。
3. **一致优先于局部最优**：某个页面"想要不一样的按钮"，先改全局组件或令牌，而不是在页面里单独写样式。
4. **无障碍不是最后一步**：设计阶段就按 [08 无障碍](08-accessibility.md) 选颜色、定尺寸、写标签。
5. **数值有出处**：规范里的数值要么来自 Apple/W3C 的公开文档，要么写明"本规范取值"并说明理由；Agent 不得自行编造"Apple 推荐 X 像素"之类的说法。
