# 7.3 布局与响应式

## 7.3.1 HIG 要点（《Layout》）

- **按重要性排序**：人们按阅读顺序（从上到下、从左到右）浏览，把最重要的内容放在顶部和左侧（起始侧）。
- **对齐与缩进**：对齐让内容好扫读；人们会把对齐的元素视为相关、把缩进的元素视为从属。
- **分组**：用留白、容器形状或分隔线表明哪些元素相关。
- **渐进披露**：内容和选项太多时，用展开/折叠、菜单或下一级页面减少首屏信息量。
- **控件与内容区分开**：控件（导航、工具栏）在视觉上与内容分层。
- **按可用空间而不是设备类型做布局**：HIG 的 size class 只看"有多少空间"，不看是手机还是平板、横屏还是竖屏。网页对应：**用视口宽度/容器宽度做断点**，不用 User-Agent 判断设备。
- **空间变化时功能不变**：只能改变"屏幕上能直接看到多少功能"，不能因为屏幕小就删功能。大空间可以把标签栏换成侧边栏、把溢出菜单里的操作摆出来。
- **尊重安全区域**：内容和控件不被刘海、圆角、系统栏遮挡。

## 7.3.2 页面骨架

所有页面共用一个布局组件（`app/Layout.tsx`），只在内容区变化：

```
宽度 ≥ 1024（lg）                          宽度 < 768（手机）
┌────────┬──────────────────────────┐     ┌──────────────────────┐
│        │ 顶栏：页面标题 · 主操作   │     │ 顶栏：标题 · 主操作   │
│ 侧边栏 ├──────────────────────────┤     ├──────────────────────┤
│ 导航   │                          │     │                      │
│        │ 内容区（max 1280 居中）   │     │ 内容区（单列）        │
│        │                          │     │                      │
│        │                          │     ├──────────────────────┤
└────────┴──────────────────────────┘     │ 底部标签栏（≤5 项）   │
                                           └──────────────────────┘
768–1023（md）：侧边栏可收起（默认展开，HIG《Sidebars》建议不要默认隐藏），或改用顶栏 + 抽屉菜单
```

- 语义结构：`<header>`、`<nav aria-label="主导航">`、`<main id="main">`、`<footer>`；页面第一个可聚焦元素是"跳到主要内容"链接（WCAG 2.4.1）。
- 每个页面有且只有一个 `<h1>`，与 `<title>` 一致（例如 `<title>账单 - 记账</title>`）。
- 内容区最大宽度 `--ds-content-max`（1280px），超宽屏两侧留白，不无限拉伸；长文本行宽 ≤ `--ds-prose-max`。
- 页面左右边距：手机 16px、平板 24px、桌面 32px（本规范取值）。

## 7.3.3 栅格

- 用 CSS Grid / Flexbox，不用固定像素宽度的浮动布局。
- 卡片栅格：`grid-template-columns: repeat(auto-fill, minmax(18rem, 1fr))`，宽度自适应，不需要为每个断点写死列数。
- 表单：手机单列；≥ md 时可以两列，但**相关字段才并排**（如"省 / 市"），并且标签在输入框上方。
- 列间距：手机 16px，≥ md 24px（本规范取值）。
- 组件内部的响应式优先用**容器查询**（`@container`，Tailwind 的 `@sm:` 等变体），让同一张卡片放在窄侧栏或宽主区都正确。

## 7.3.4 断点下的行为

| 元素 | < 768 | 768–1023 | ≥ 1024 |
|---|---|---|---|
| 主导航 | 底部标签栏（≤ 5 个一级入口）或顶栏"菜单"按钮 + 抽屉 | 可收起的侧边栏 | 常驻侧边栏 |
| 页面主操作 | 顶栏右侧按钮；列表页可用页面底部固定按钮（注意安全区域） | 顶栏右侧 | 顶栏右侧 |
| 数据表格 | 改为卡片列表，或表格放进**只有表格自己横向滚动**的容器 | 表格，次要列可隐藏 | 完整表格 |
| 弹窗 | 底部抽屉（sheet）或全屏 | 居中弹窗 | 居中弹窗 |
| 筛选条件 | 收进"筛选"按钮打开的抽屉 | 顶部一行 | 顶部一行或左侧栏 |
| 次要操作 | 收进"更多"菜单 | 部分展开 | 全部展开 |

## 7.3.5 安全区域与视口

- `index.html`：`<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">`；**不要**加 `user-scalable=no` 或 `maximum-scale=1`（见 06-frontend.md）。
- 使用 `viewport-fit=cover` 后，固定在底部/顶部的元素要加安全区内边距：`padding-bottom: max(var(--ds-space-4), env(safe-area-inset-bottom))`（MDN《env()》）。
- 手机上的全屏高度用 `100dvh`（动态视口高度）而不是 `100vh`，避免被浏览器地址栏遮挡。
- 吸顶/吸底元素不能挡住获得焦点的元素（WCAG 2.4.11）：给滚动容器设置 `scroll-padding-top` / `scroll-padding-bottom` 等于顶栏/底栏高度。

## 7.3.6 同页对齐

- **同一页面内的面板、输入行、列表和高亮底色，左右边线必须对齐。** 分段栏、筛选栏、新建输入行、分隔线、列表行，以及选中行/悬停行的高亮底色，都占满同一个内容区：左右边线像素级一致。
- 列表行的左右内边距用一个 CSS 变量统一控制（例如 `--row-pad-x`），选中、悬停、普通行用同一个值；高亮只改背景色和圆角，不改内边距、外边距或边框宽度，不用负外边距把底色"撑出去"。
- 输入行里的文字起点与列表行标题起点对齐：输入框左内边距 = 行内边距 + 前置图标列宽 + 列间距（减去输入框边框宽度）。
- 并排的面板（列表 + 右侧编辑栏）顶部对齐。
- **改 UI 的 PR 必须附截图**（至少 1280 宽桌面），审查时要检查对齐：对照同一页面上其他行，必要时用开发者工具量 `getBoundingClientRect()` 的 left / right。见 [09-review-checklist.md](09-review-checklist.md)。

## 7.3.7 从右到左与国际化

默认中文界面，但布局用**逻辑属性**（`margin-inline-start`、`padding-inline`、`inset-inline-end`，Tailwind 的 `ms-*`、`pe-*`）而不是 left/right，未来支持其他语言成本最低。日期、数字、金额用 `Intl.DateTimeFormat` / `Intl.NumberFormat` 按 `zh-CN` 格式化，不手写拼接。
