# 7.9 设计审查清单（声称"界面做完了"之前必须执行）

> Agent 在交付任何界面改动前，**逐项执行本清单**，把结果和截图放进交付报告（[templates/delivery-report.md](../../templates/delivery-report.md)）。没有截图 = 没有验证 = 没做完。
> 本清单是 03-verification.md 浏览器验证和 [06-frontend.md](../06-frontend.md) 6.9 的设计部分补充。

## 第 1 步：生成截图与自动扫描

1. 把 [templates/ui-review.spec.ts](../../templates/ui-review.spec.ts)（本仓库已在一个使用 design-tokens.css 的示例页面上用 Playwright + Chromium 实际跑通）复制到 `web/e2e/`，在 `PAGES` 中列出本次改动涉及的页面（包括空状态、出错状态能稳定复现的地址）。
2. 在**测试环境的真实后端 + 测试数据**上运行：`npx playwright test e2e/ui-review.spec.ts`。
3. 得到 `页面 × 3 个宽度（390 / 768 / 1280）× 2 种模式（浅色 / 深色）` 的整页截图，同时脚本会检查：
   - 没有横向滚动（WCAG 1.4.10）；
   - axe 自动扫描没有 serious / critical 级别问题（WCAG A / AA 规则）。
4. **逐张打开截图看**，不要只看测试是否通过。截图附到交付报告；文件太多时至少附：每个改动页面的 390 浅色、390 深色、1280 浅色、1280 深色。

## 第 2 步：逐项检查

### 令牌与视觉一致性
- [ ] 组件代码里没有裸色值、裸像素字号、`z-index` 魔法数字（`rg -n "#[0-9a-fA-F]{3,8}\b|z-index:\s*[0-9]{3,}" web/src` 只应命中 `design-tokens.css`；`#main` 这类锚点可能误报，逐条确认）
- [ ] 改过颜色令牌：`python3 check-contrast.py web/src/styles/design-tokens.css` 全部 PASS（附输出）
- [ ] 间距都是 4 的倍数；组内间距小于组间间距
- [ ] 圆角、阴影只用令牌中的几档；嵌套圆角同心
- [ ] 同一种操作在各页面外观一致（按钮样式、图标、文字）

### 布局与响应式（看截图）
- [ ] 390px：单列、无横向滚动、无文字被截断或重叠、底部固定元素没有遮住内容
- [ ] 768px：导航形态正确（可收起侧边栏或顶栏菜单）
- [ ] 1280px：侧边栏常驻，内容不无限拉宽
- [ ] 同一页面内的面板、输入行、列表和高亮底色，左右边线对齐（对照同页其他行，必要时量 `getBoundingClientRect()`）；并排面板顶部对齐；PR 已附截图（见 [03-layout.md](03-layout.md) 7.3.6）
- [ ] 最重要的内容在页面顶部/左侧；每页一个 `<h1>`，与 `<title>` 对应
- [ ] 浏览器缩放 200% 后内容和功能完整

### 浅色 / 深色
- [ ] 两种模式下所有文字清晰可读，没有"深色背景上的深色文字"
- [ ] 深色模式下弹窗、菜单比页面背景更亮（elevated），能看出层次
- [ ] 原生控件（下拉框、日期选择、滚动条）随模式切换（`color-scheme`）
- [ ] 图片、Logo、图表在两种模式下都清晰

### 组件状态
- [ ] 每个按钮有 default / hover / active / focus-visible / disabled / loading 状态
- [ ] 每个区域的四种数据状态都检查过：加载中、空、出错（有重试）、有数据——附截图或说明如何复现
- [ ] 表单：每个输入有可见标签；错误显示在字段旁且说明怎么改；提交中不能重复提交；提交失败不清空输入
- [ ] 每个区域最多一到两个主按钮；危险操作不是主按钮；确认框的取消按钮叫"取消"
- [ ] 弹窗：一次只有一个；Esc 可关闭；关闭后焦点回到触发按钮；有未保存内容时关闭前确认

### 交互与动效
- [ ] 每次点击 100ms 内有视觉反馈
- [ ] 常见删除提供撤销，只有不可逆操作才弹确认
- [ ] 错误提示和带"撤销"的提示不会在用户读完前自动消失
- [ ] 模拟 `prefers-reduced-motion: reduce` 后，弹窗/抽屉/菜单没有位移和缩放
- [ ] 没有自动轮播、无限循环的装饰动画

### 无障碍
- [ ] 只用键盘完成主流程，焦点始终可见、不被吸顶/吸底栏遮挡
- [ ] 触屏主要控件 ≥ 44×44，任何控件 ≥ 24×24（开发者工具量一下图标按钮）
- [ ] 纯图标按钮有 `aria-label` 和悬停提示
- [ ] 状态不只靠颜色表达
- [ ] `<html lang="zh-CN">`；语义元素正确（按钮是 `<button>`，表格是 `<table>`）
- [ ] 动态消息（保存成功、错误）有 `role="status"` / `role="alert"`

### 图标与文案
- [ ] 全项目只用一套图标库；没有 SF Symbols、没有 Apple 图形；没有打包 SF 字体
- [ ] 按钮文字是动词；没有"确定/提交/是/否"作为有后果操作的按钮
- [ ] 错误信息说明怎么改，没有"我们""哎呀""无效"
- [ ] 空状态有下一步操作
- [ ] 中英文/数字之间有空格；全角标点；术语与术语表一致
- [ ] 页面上没有 `undefined`、`null`、`NaN`、`[object Object]`、错误堆栈、"Lorem ipsum"、假数据

## 第 3 步：在交付报告中写明

```markdown
### 界面审查（docs/07-design-system/09-review-checklist.md）
- 审查页面：/records、/records/new（连接测试环境真实后端，测试库 app_test）
- 截图：e2e/screenshots/（共 12 张，下方附 4 张）
- 自动检查：ui-review.spec.ts 12 passed（无横向滚动；axe 无 serious/critical）
- 对比度：check-contrast.py 全部达标（本次未改颜色 / 附输出）
- 手动检查：键盘主流程 ✅；200% 缩放 ✅；减少动效 ✅；四种数据状态 ✅（空状态截图见附件）
- 未通过 / 未覆盖：出错状态只在本地断网模拟过，未在测试环境复现
```

**有任何一项未通过，就如实写"未通过"和原因，不能写"界面已完成"。**
