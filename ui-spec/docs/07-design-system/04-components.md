# 7.4 组件规范

每个组件按同一结构说明：**用途 → 尺寸 → 状态 → 规则 → 该做 / 不要 → 实现要点**。所有颜色、尺寸都引用 [02 设计令牌](02-tokens.md)。

通用状态定义（适用于所有可交互组件）：

| 状态 | 触发 | 视觉要求 |
|---|---|---|
| default 默认 | — | 能看出"可以操作"（按钮有背景或边框，链接有颜色+下划线或位置提示） |
| hover 悬停 | 鼠标悬停（只在支持悬停的设备：`@media (hover: hover)`） | 背景/边框轻微变化，`--ds-duration-instant` 过渡 |
| active 按下 | 按下瞬间 | **必须有按下态**（HIG《Buttons》："Always include a press state for a custom button"）：颜色更深或轻微缩小（缩小只在 `motion-safe` 下） |
| focus-visible 键盘焦点 | Tab 键聚焦 | 2px `--ds-focus-ring` 外框 + 2px 偏移，不能被裁掉或遮住 |
| disabled 禁用 | 暂时不可用 | 降低不透明度（约 0.4–0.5）+ `cursor: not-allowed`；仍要说明为什么不可用（旁边文字或提示） |
| loading 处理中 | 已提交、等待结果 | 显示加载指示，**防止重复提交**，文字可改为"保存中…" |

实现原则：**先用原生 HTML 元素**；原生没有的复杂组件（菜单、组合框、标签页、提示气泡）按 WAI-ARIA APG 的模式实现，或使用遵循 APG 的无头组件库（选型写 ADR）。

## 7.4.1 按钮（Button）

**用途**：触发一个立即发生的操作。跳转页面用链接 `<a>`，不用按钮。

**样式层级**（HIG《Buttons》：用"样式"而不是"大小"区分首选项；每个视图的醒目按钮保持一到两个）：

| 样式 | 外观 | 用于 |
|---|---|---|
| primary 主要 | `--ds-accent-bg` 实心 + `--ds-on-accent` 文字 | 当前视图最可能执行的操作，每个区域最多 1 个 |
| secondary 次要 | `--ds-surface` 背景 + `--ds-border-control` 边框 + `--ds-text` 文字 | 其他操作 |
| tertiary / ghost 文字按钮 | 无背景，`--ds-accent` 文字 | 低优先级操作、"取消" |
| destructive 危险 | `--ds-danger-bg` 实心或 `--ds-danger` 文字 | 删除、清空等不可逆操作 |

**角色**（HIG《Buttons》Role）：primary（默认按钮，可响应 Enter）、cancel（取消）、destructive（会销毁数据）。**不要把危险操作设为 primary**——HIG 指出人们有时不读就点醒目按钮。

**尺寸**：

| 尺寸 | 高度 | 水平内边距 | 字号 | 用于 |
|---|---|---|---|---|
| sm | 32px | 12px | subhead 14px | 仅桌面密集区域（表格行内） |
| md（默认） | 44px | 16px | body 16px | 绝大多数场景 |
| lg | 48px | 20px | body 16px 600 | 移动端页面主操作、底部固定按钮 |

图标按钮：正方形，md 为 44×44，图标 20px。按钮之间间距 ≥ 12px（HIG 带边框元素周围约 12pt）。

**状态**：

| 状态 | primary | secondary | destructive |
|---|---|---|---|
| default | accent-bg | surface + control 边框 | danger-bg |
| hover | accent-bg-hover | 背景混入 4–8% 文字色 | 加深 |
| active | 比 hover 再深一级 | 再深一级 | 再深一级 |
| focus-visible | 焦点环 | 焦点环 | 焦点环 |
| disabled | 不透明度 0.45 | 不透明度 0.45 | 不透明度 0.45 |
| loading | 左侧转圈 + "保存中…"，宽度不跳动，`aria-busy="true"`，禁止再次点击 | 同左 | 同左 |

**该做**
- 文字以动词开头、说清结果："保存"、"新增记录"、"导出 CSV"（HIG《Writing》《Buttons》）。
- 并排的选项按钮大小相同，用样式区分首选。
- 对话框里主按钮在右（行尾）、"取消"在左；纵向堆叠时主按钮在上（HIG《Alerts》）。

**不要**
- 一个区域里放三个实心主按钮。
- 用"确定"、"提交"、"好的"作为会产生后果的按钮文字。
- 用 `<div onClick>` 做按钮；用按钮做页面跳转。
- 去掉焦点样式，或者只在悬停时显示按钮。

**实现要点**：`<button type="button">`（表单提交按钮写 `type="submit"`）；纯图标按钮必须有 `aria-label`，并提供悬停提示文字；加载中用 `disabled` 防重复，或保持可聚焦并在点击处理里忽略重复提交。

## 7.4.2 输入框与表单（Text field / Form）

**用途**：输入少量文字（HIG《Text fields》）。大段文字用 `<textarea>`。能选就不要让人打字（HIG《Entering data》："offer choices instead of requiring text entry"）。

**结构**（从上到下）：标签（必有）→ 输入框 → 帮助文字（可选，`--ds-text-footnote` + `--ds-text-tertiary`）→ 错误文字（出错时，`--ds-danger` + 错误图标）。

**尺寸**：高度 44px（`--ds-control-h-md`），字号 16px（业界常见经验：iOS Safari 聚焦字号小于 16px 的输入框时会自动放大页面；此点未在 Apple 官方文档中核实），内边距水平 12px，圆角 `--ds-radius-md`，边框 1px `--ds-border-control`。宽度与预期内容长度相称（HIG："match the size of a text field to the quantity of anticipated text"）——邮编框不要和地址框一样宽。

**状态**：

| 状态 | 视觉 |
|---|---|
| default | control 边框，surface 背景 |
| hover | 边框加深 |
| focus | 焦点环（2px accent）；不要只靠边框变色 |
| filled | 同 default |
| error | danger 边框 + 下方错误文字 + 图标；`aria-invalid="true"`，错误文字用 `aria-describedby` 关联 |
| disabled | 不透明度 0.45，`sunken` 背景 |
| read-only | 无边框或虚线，`sunken` 背景，文字可选中复制 |

**规则**（HIG《Text fields》《Entering data》《Writing》+ WCAG 3.3）

- **每个输入框都有可见的 `<label>`**。占位符只是示例（"name@example.com"），输入后会消失，不能代替标签。
- 必填/选填：哪种少标哪种（多数必填时标"（选填）"），不要只靠红色星号。
- 用正确的输入类型，让手机弹出合适键盘：`type="email"`、`type="tel"`、`inputmode="decimal"`（金额）、`inputmode="numeric"`（验证码）；并设置 `autocomplete`（`email`、`current-password`、`one-time-code` 等），让浏览器自动填充（WCAG 3.3.7 避免重复输入）。
- 密码用 `type="password"`，**永远不要预填密码**（HIG《Entering data》）；提供"显示密码"按钮。
- **校验时机**（HIG《Text fields》）：邮箱这类格式在离开字段（blur）时校验；创建用户名、密码这类规则在输入过程中即时提示。提交时再整体校验一次，并把焦点移到第一个错误字段，同时在表单顶部列出错误摘要。
- 错误信息说明**怎么改**，而不是指责：写"密码至少 8 位"，不写"密码太短"或"无效输入"（HIG《Writing》的例子）。
- 金额、数量：按 `zh-CN` 显示千分位和小数位；提交前去掉格式符号；不要假设所有用户的格式都一样。
- 字段纵向排列、宽度一致、间距均匀；Tab 键顺序与视觉顺序一致。
- 关于"未填完时禁用提交按钮"：HIG 允许"未提供必需数据前让继续按钮不可用"。网页上本规范倾向于**保持提交按钮可用、点击后指出缺什么**，因为禁用按钮无法获得焦点、也不会告诉用户原因；若确实禁用，旁边必须写明还缺什么。
- 长表单分步骤或分组（`<fieldset>` + `<legend>`），并允许返回修改。

**该做**：标签在上、输入框在下；错误紧贴字段；保留用户已填内容。
**不要**：只用占位符当标签；提交失败后清空表单；在用户还没输入完时就弹红色错误；用浮动标签把标签缩到看不清。

**选择类控件**：
- 2–5 个互斥选项且需要一眼看到：单选按钮组（`<fieldset>` + `<input type="radio">`）或分段控件；更多选项：`<select>` 或可搜索的组合框。
- 开/关设置：开关（`role="switch"` 或复选框），标签描述"开启时会怎样"（HIG《Writing》："Describe what it does when turned on"），立即生效；需要点"保存"才生效的用复选框。

## 7.4.3 列表与表格（List / Table）

**用途**：按行展示数据。文本型、需要扫读的数据优先用列表或表格；大小差异大或以图片为主的内容用卡片栅格（HIG《Lists and tables》）。

**尺寸**：列表行最小高度 44px（可点击行）；表格行高 舒适 48px / 紧凑 40px（桌面，本规范取值）；单元格水平内边距 12–16px；表头 `--ds-text-subhead` 600 字重、`--ds-sunken` 背景或底边线。

**状态**：

| 状态 | 视觉 |
|---|---|
| default | surface 背景，行间 separator 线 |
| hover（可点击行） | 背景混入 4% 文字色 |
| focus-visible | 整行焦点环（内描边） |
| selected 选中 | `--ds-accent-soft` 背景 + 复选框/对勾（不能只靠背景色） |
| disabled | 不透明度 0.45 |

**规则**

- 列标题用名词或名词短语，不加句末标点（HIG《Lists and tables》）。
- 选中反馈（HIG）：用于导航的列表持续高亮当前项；用于选择选项的列表在点击后显示对勾。
- 文字简短，避免截断；必须截断时，文件名一类内容可用中间省略（保留开头和结尾），并提供查看全文的方式（`title` 或详情页）。
- 数字列右对齐并用 `tabular-nums`；文字列左对齐；金额带单位或货币符号；空值显示"—"，不显示 `null` / `undefined`。
- 可排序列：表头是按钮，显示当前排序方向，`aria-sort` 标明。
- 数据多时分页或虚拟滚动；显示总数（"共 128 条"）。
- 行内操作 ≤ 2 个直接显示，其余放进"更多"菜单。
- 手机宽度：改为卡片列表（每张卡片：主标题、关键数值、次要信息、操作），或表格放在 `overflow-x: auto` 的容器里，只让表格横向滚动。

**该做**：用 `<table>` + `<thead>` + `<th scope="col">` 展示二维数据；空表格显示空状态（见 7.4.10）。
**不要**：用一堆 `<div>` 模拟表格；表头和单元格对齐方式不一致；整页横向滚动。

## 7.4.4 卡片（Card）

**用途**：把一组相关信息框在一起，例如看板上的一个指标、列表在手机上的一行。

**规格**：`--ds-surface` 背景、`--ds-radius-lg`、内边距 16px（手机）/ 24px（桌面）、浅色模式 `--ds-shadow-1` 或 1px separator 边框（二选一）、深色模式靠背景层级。卡片之间间距 16–24px。

**状态**：整张卡片可点击时，有 hover（阴影或背景变化）、active、focus-visible（整卡焦点环）；**整卡可点击时卡片里不要再放其他按钮**（嵌套交互元素），否则把卡片标题做成链接、用伪元素扩展点击区域。

**该做**：一张卡片一个主题；标题 + 关键数字 + 说明的层级清楚；数字带单位和时间范围（"本月支出 ¥3,280"）。
**不要**：卡片套卡片；为了"丰富"把所有内容都装进卡片；卡片高度写死导致字号放大时文字溢出。

## 7.4.5 导航：侧边栏、顶栏、底部标签栏

### 侧边栏（Sidebar，≥ 1024px）

HIG《Sidebars》要点 → 网页规则：
- 放一级导航（应用的主要区域）；**最多两级**层级，更深的层级放到内容区的列表里。
- 两级时用简短的分组标题，可折叠（`<details>` 或带 `aria-expanded` 的按钮）。
- 用熟悉的图标 + 文字标签；图标颜色有明确含义才用彩色。
- 允许收起侧边栏，但**不要默认隐藏**（保持可发现）。
- 当前页：`aria-current="page"` + 高亮背景（`--ds-accent-soft`）+ 字重或指示条（不只靠颜色）。
- 宽度 240–280px（本规范取值），收起后 64px 只显示图标（必须有悬停提示和 `aria-label`）。

### 顶栏（Top bar / Toolbar）

- 左：页面标题（或返回按钮 + 标题）；右：本页主操作（最多 1 个主按钮）+ 少量图标按钮 + "更多"菜单。
- 高度 56px（手机）/ 64px（桌面）（本规范取值）；吸顶时用 `--ds-z-sticky`，滚动后可加底边线区分内容。
- HIG《Toolbars》：控件分成逻辑分组；不要放太多项，优先放用户最常用的命令；确实放不下时才加"更多"菜单，把较不重要的操作放进去；主操作（如"完成"）放在行尾并始终可见。

### 底部标签栏（Tab bar，< 768px 可选）

HIG《Tab bars》要点 → 网页规则：
- **只用于导航，不放操作**（"新增"按钮不放在标签栏里，放到页面上）。
- 在各一级页面**始终可见**；只有全屏弹窗可以盖住它。
- **不要禁用或隐藏某个标签**；某个区域暂时没内容，就进去后显示空状态说明原因。
- 数量少而精，默认 **5 个或更少**（HIG 在可定制标签栏处给出"five or fewer"）；超过就改用侧边栏/抽屉，避免"更多"标签。
- 每个标签：图标 + 文字（中文 2–4 个字），整个标签都是点击区域（≥ 44×44）；当前标签用填充图标 + 强调色 + `aria-current="page"`。
- 徽标（红点/数字）只用于需要关注的关键信息，不滥用。
- 底部加 `env(safe-area-inset-bottom)` 内边距。

**该做**：同一个导航结构在不同宽度下保持一致的入口和顺序，只改变呈现形式（标签栏 ↔ 侧边栏）——HIG《Layout》"保持功能不变"。
**不要**：手机上用汉堡菜单藏起所有一级入口的同时又没有任何可见导航；导航项文字过长被截断。

## 7.4.6 弹窗与抽屉（Modal dialog / Sheet）

HIG《Modality》《Sheets》要点：
- **只在有明确好处时使用模态**：需要用户专注完成一个范围明确的小任务，或必须先确认/补充信息。
- 模态任务简短；不要在弹窗里做出"应用中的应用"（多层导航）。
- **一次只显示一个弹窗/抽屉**；需要另一个时先关闭当前的。
- 始终有明显的关闭方式；标题说明任务（"新增记录"）。
- 关闭会丢失用户输入时，先确认（提供"保存 / 放弃 / 继续编辑"）。
- 抽屉内的按钮：取消（关闭不保存）、完成/保存（保存并关闭）、返回（多步流程上一步）；有"完成"就要配"取消"或"返回"；三者不要同时出现。
- 复杂、长流程考虑整页而不是弹窗。

**网页形态**：

| 形态 | 何时用 | 规格 |
|---|---|---|
| 居中弹窗 dialog | 桌面上的小任务、确认 | 宽 min(32rem, 100% − 32px)，`--ds-elevated`，`--ds-radius-xl`，`--ds-shadow-3`，遮罩 `--ds-scrim` |
| 底部抽屉 sheet | 手机上的小任务 | 全宽，顶部圆角 `--ds-radius-xl`，最大高度 90dvh，内部滚动，底部安全区 |
| 侧边抽屉 drawer | 桌面上需要参照背景内容的编辑、详情 | 宽 24–32rem，从行尾滑入 |
| 全屏 | 手机上的复杂表单 | 顶栏：取消 · 标题 · 保存 |

**状态**：打开（`--ds-duration-normal` 淡入 + 轻微位移，减少动效时只淡入）、关闭、提交中（按钮 loading，禁止重复提交，禁止点遮罩关闭以免丢失）。

**实现要点**（MDN《dialog》、WAI-ARIA APG《Dialog (Modal)》）：
- 优先用原生 `<dialog>` + `showModal()`：自动进入 top layer、背景不可交互、Esc 触发 `cancel` 事件。
- 打开时焦点移入弹窗（第一个输入框，或无输入框时的标题/关闭按钮）；Tab 在弹窗内循环；Esc 关闭；**关闭后焦点回到触发它的按钮**。
- `aria-labelledby` 指向标题；页面背景滚动锁定。

**不要**：弹窗套弹窗；打开页面就弹窗；用弹窗显示纯信息；没有关闭按钮只能点遮罩。

## 7.4.7 确认框（Alert）

HIG《Alerts》要点 → 网页规则：
- **少用**：只用于需要立即知道并处理的关键信息；纯信息不要用确认框，放在页面上下文里。
- **常见、可撤销的删除不弹确认**，改为执行 + 提供"撤销"；只有**不常见且不可撤销**的破坏性操作才弹确认。
- 不要在页面打开时弹确认框（例如"网络不可用"应在页面上用不打扰的提示显示，并显示缓存数据）。
- **标题**说清发生了什么："删除 3 条记录？"、"无法连接服务器"；不要写"错误"或"错误 329347"；不超过两行。
- **说明文字**只在有价值时加，简短完整的句子。不要解释按钮。
- **按钮**：一到两个词、动词、与标题呼应："删除"、"放弃修改"、"重试"；只在纯信息提示里用"好"；**取消按钮永远叫"取消"**；不用"是 / 否"。
- 最多三个按钮；主按钮在行尾（右）或堆叠的最上方，取消在行首（左）或最下方。
- 用户没有主动选择的破坏性操作，按钮用危险样式；用户本来就是要删除（如点了"清空回收站"）时，确认按钮可以不用危险样式，但要有"取消"。
- 支持 Esc 取消；不要把"取消"设为默认按钮；希望用户先读内容时，不设任何默认按钮。

**实现**：`<dialog>` + `role="alertdialog"`，`aria-describedby` 指向说明文字；打开时焦点放在最安全的按钮（通常是"取消"）。

## 7.4.8 轻提示与横幅（Toast / Banner）

**用途**：非阻断的状态反馈。HIG《Feedback》：反馈方式要与信息的重要程度匹配——状态信息被动显示，可能丢数据的警告才打断用户。

| 类型 | 何时用 | 规则 |
|---|---|---|
| 行内提示 | 某个区域的状态（"已同步 · 2 分钟前"） | 首选；放在相关内容旁边（HIG："integrating status feedback into your interface"） |
| 轻提示 toast | 用户操作的结果（"已删除 1 条记录"+"撤销"） | 位置：桌面右下或顶部居中，手机底部（在标签栏上方）；同时最多 3 条 |
| 横幅 banner | 影响整个页面的持续状态（离线、维护） | 页面顶部，持续显示直到状态消失，可关闭 |
| 表单错误 | 校验失败 | 不用 toast，显示在字段旁 + 表单顶部摘要 |

**计时规则**（HIG《Accessibility》建议尽量少用自动消失的界面元素；WCAG 2.2.1 Timing Adjustable）：
- **错误和带操作按钮（如"撤销"）的提示不自动消失**，或在鼠标悬停/键盘聚焦时暂停计时并给足时间。
- 纯成功提示可以自动消失（本规范取 5 秒以上），消失不影响任何操作。
- 重要的成功（如付款成功）才需要明确确认；普通保存成功用轻量反馈即可（HIG《Feedback》："they only need to know when it doesn't"）。

**实现**：容器常驻 DOM，使用 `role="status"`（普通）或 `role="alert"`（错误）/ `aria-live`，让读屏软件不移动焦点也能播报（WCAG 4.1.3 Status Messages）；关闭按钮 ≥ 44×44；图标 + 文字 + 颜色三者同时表达类型。

## 7.4.9 菜单（Menu）

HIG《Menus》要点 → 网页规则：
- 菜单项标签用动词或动词短语，简洁清楚（"重命名"、"导出 CSV"）。
- **需要进一步输入才能完成的项，结尾加省略号"…"**（"重命名…" 打开输入框）。
- 常用项放前面；相关项分组，用分隔线隔开；组内要么都有图标、要么都没有。
- 菜单不要太长；子菜单只用一层，子菜单超过约 5 项考虑拆分。
- 不可用的项**显示为禁用而不是隐藏**；即使全部项都不可用，菜单本身仍能打开。
- 开关类项用对勾表示当前状态，或用随状态变化的标签（"显示地图 / 隐藏地图"）。
- 危险项（删除）放在最后一组，用危险色文字。

**尺寸**：菜单项高度 ≥ 44px（触屏）/ 36px（仅桌面指针，仍 ≥ 24px）；菜单宽度 12–20rem；`--ds-elevated` + `--ds-radius-lg` + `--ds-shadow-2`。

**状态**：项的 hover / 键盘高亮（同一视觉）、focus、disabled、checked。

**实现**（WAI-ARIA APG《Menu Button》）：触发按钮 `aria-haspopup="menu"` + `aria-expanded`；Enter / Space / ↓ 打开并聚焦第一项，↑ 聚焦最后一项；方向键移动、Esc 关闭并把焦点还给按钮；点击外部关闭。导航链接列表不必用 `role="menu"`，用普通 `<nav>` + 链接即可。

## 7.4.10 空状态、加载状态、错误状态

每个数据区域必须实现四种状态（06-frontend.md 6.4）：

| 状态 | 规格 | 来源 |
|---|---|---|
| **加载中** | 尽快显示内容骨架（与真实布局同形状的灰块，`--ds-sunken`）；请求很快时不闪烁加载态（延迟约 300ms 再显示，本规范取值）；知道进度用进度条，不知道用不确定指示器；加载期间其他区域仍可操作 | HIG《Loading》："Show something as soon as possible"；《Progress indicators》 |
| **空** | 图标或简单插图（可选）+ 一句说明为什么是空的 + **下一步操作按钮**（"新增第一条记录"）；区分"还没有数据"和"筛选后没有结果"（后者给"清除筛选"） | HIG《Writing》："Provide clear next steps on any blank screens" |
| **出错** | 说清发生了什么 + 用户能做什么 + "重试"按钮；保留已加载的数据；不显示技术堆栈；不写"我们" | HIG《Writing》《Alerts》 |
| **有数据** | 正常展示；后台刷新时不清空现有内容，只在角落显示刷新中 | — |

**不要**：一直转圈没有超时；空白页面什么都不显示；把错误码当提示文字；空状态里放会消失的关键信息（HIG：空状态通常是暂时的）。

## 7.4.11 搜索（Search）

HIG《Searching》《Search fields》要点 → 网页规则：
- 搜索重要时放在显眼位置（顶栏或列表顶部）；全站尽量只有一个搜索入口，分区内的搜索作为当前视图的筛选。
- 占位符说明搜索范围（"搜索账单"）；有范围切换时清楚显示当前范围。
- 可显示最近搜索和联想建议；**显示搜索历史要考虑隐私，并提供清除方式**。
- 输入时防抖（约 300ms，本规范取值）后自动搜索，或按 Enter 搜索——同一应用里统一一种。
- `<input type="search">` 放在 `<form role="search">` 或 `<search>` 中；有清除按钮；结果数量通过 `role="status"` 播报。
