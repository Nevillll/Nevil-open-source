# 7.7 界面文案（UX Writing）

界面上的文字是体验的一部分（HIG《Writing》）。本篇把 HIG 的写作原则翻译成**简体中文界面**的规则，并结合《中文文案排版指北》处理中文排版。

## 7.7.1 原则（HIG《Writing》）

- **确定语气（voice）**：管理工具的语气是"清楚、可靠、平实"。建一个**术语表**（`docs/glossary.md`），同一个东西全站只用一个词——"记录"就不要再出现"条目""数据项"。
- **语调随场景变化**：出错和涉及金钱时直接、严肃；完成目标时可以轻松一点。
- **清楚**：每个词都要有必要；能少写就少写；拿不准时读出来。
- **为所有人写**：简单平实，不用行话和内部代号，不用性别化的称呼。
- **以行动为导向**：按钮和链接用动词；不用"点这里"作为链接文字，链接文字要说明去哪（"查看导入说明"）。
- **少用物主代词**："收藏"比"我的收藏"简洁；用了就全站一致。**不要用"我们"**（"我们无法加载内容"不清楚"我们"是谁，写"无法加载内容"）。
- **按设备说话**：触屏上不说"点击"、桌面上不说"轻触"；网页同时面向两者，用中性的"选择"、"打开"，或直接写操作名。
- **空状态给出下一步**，最好附按钮。
- **错误信息**：放在出错位置旁边；不指责；说清怎么改；不用"哎呀""糟糕"这类语气词。
- **设置项**：标签简单直接；需要解释时，说明"开启后会怎样"，用户能推断关闭时的情况。
- **输入提示**：标签说明要什么，占位符给格式示例。

## 7.7.2 按钮与操作文案

| 场景 | ✅ 这样写 | ❌ 不要这样写 | 理由 |
|---|---|---|---|
| 保存表单 | 保存 | 确定 / 提交 / OK | 说清结果 |
| 删除确认框按钮 | 删除 | 是 / 确定 | HIG《Alerts》：避免"是/否"，用具体动词 |
| 取消 | 取消 | 算了 / 不了 / 关闭（在确认框中） | HIG：取消按钮永远叫"取消" |
| 多步流程 | 开始 → 下一步 → 完成 | 继续 / 下一步 / 前进 混用 | HIG：多步流程用词保持一致，结束用"完成" |
| 需要更多输入的菜单项 | 重命名… | 重命名 | HIG《Menus》：省略号表示还需要输入 |
| 链接 | 查看导入说明 | 点击这里 | 读屏用户需要链接文字本身有意义 |
| 开关标签 | 每天发送汇总邮件 | 是否发送汇总邮件？ | 描述开启后的效果 |

规则：按钮 2–4 个汉字为宜，**不加句号**；同一操作全站同一个词（"新增"还是"添加"，选一个写进术语表）。

## 7.7.3 提示与错误文案

结构：**发生了什么 + （原因）+ 用户能做什么**。

| ✅ | ❌ |
|---|---|
| 密码至少 8 位 | 密码太短 / 无效密码 |
| 金额只能输入数字，例如 35.50 | 格式错误 |
| 无法连接服务器。请检查网络后重试。[重试] | 网络错误 Error: ECONNREFUSED |
| 这个邮箱已注册。[去登录] | 邮箱重复 |
| 没有找到"午餐"相关的账单。[清除搜索] | 暂无数据 |
| 还没有任何记录。[新增第一条记录] | （空白页面） |
| 已删除 3 条记录。[撤销] | 操作成功！ |
| 删除 3 条记录？删除后无法恢复。[取消] [删除] | 您确定要执行此操作吗？[否] [是] |

- 告诉用户怎么做，而不是只说规则不允许什么：写"姓名请只用文字"，不写"不能包含数字或符号"（HIG《Writing》）。
- 技术细节（错误码、请求 ID）可以放在"详细信息"折叠区里，供排查使用，不作为主要文案。
- 不在前端拼接后端原始错误信息展示给用户；后端错误码在 `src/api/` 中映射为中文提示（见 06-frontend.md）。
- 确认框标题是完整问句时用问号；说明文字用完整句子和句号。

## 7.7.4 中文排版规则

依据《中文文案排版指北》（sparanoid/chinese-copywriting-guidelines）：

- **中英文之间加空格**：`使用 GitHub 登录`。
- **中文与数字之间加空格**：`共 128 条记录`。
- **数字与单位之间加空格**：`10 GB`、`20 分钟`；例外：度数和百分比不加，`90°`、`15%`。
- **全角标点与其他字符之间不加空格**：`已保存，共 3 条。`
- **使用全角中文标点**：，。？！：；""（）；不重复使用标点（不写"！！！"）。
- **数字使用半角**：`3,280`，不写 `３２８０`。
- **完整的英文句子、特殊名词内部使用半角标点**。
- **专有名词使用正确的大小写**：GitHub、iOS、JavaScript，不写 github、IOS。
- 不用不地道的缩写：写"TypeScript、HTML5"，不写"Ts、h5"。

本规范补充（项目统一即可）：
- 引号：简体中文界面统一用 `“”`。指北把"简体中文使用直角引号「」"列为**有争议**的做法；用哪种都可以，但全站只选一种。
- 日期时间：`2026-10-15 14:30` 或 `10月15日 14:30`（同一界面只用一种）；相对时间"5 分钟前"超过 7 天改为具体日期（本规范取值）。
- 金额：`¥3,280.00`，负数用 `-¥35.00` 并配"支出"文字或图标，不只靠红色。
- 数量为 0 时说清楚："没有未读消息"，而不是"0 条未读消息"。

## 7.7.5 文案检查清单

- [ ] 所有按钮以动词开头，没有"确定/提交/是/否"作为有后果操作的按钮
- [ ] 确认框标题说清后果，取消按钮叫"取消"
- [ ] 所有错误信息说明怎么改，没有"无效""错误"等无信息词，没有"我们""哎呀"
- [ ] 每个空状态都有下一步操作
- [ ] 术语与 `docs/glossary.md` 一致
- [ ] 中英文、中文与数字之间有空格；全角标点；无重复标点
- [ ] 页面上没有显示 `undefined`、`null`、`NaN`、`[object Object]`、原始错误堆栈
